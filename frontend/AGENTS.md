# Frontend Rules

Gotchas specific to `frontend/` (Next.js/React/TailwindCSS, plus Playwright E2E under `frontend/tests/e2e/`). Cross-cutting rules (git practices, code quality, testing policy, safety-critical prohibitions) live in `.ai/rules/core.md` at the repo root — read that first. This file follows the same multi-agent convention as the root `AGENTS.md`: `frontend/CLAUDE.md` is a symlink to this file so Claude Code loads it automatically when working under `frontend/`, and other agents (Codex, etc.) can read `AGENTS.md` directly.

| A second `crm-api` left attached to the E2E database                             | Any other crm-api pointed at `personal_crm_test` — a leftover from a killed E2E run, another worktree's stack, on ANY port — runs its own River client and can dequeue the backend-under-test's jobs. Job state that lives IN MEMORY in the process that minted it (`service.RematchService`) then never becomes terminal: `river_job` reads `completed` while `GET /rematch/jobs/:id` reports `running` forever, and `rematch-on-add-email.spec.ts` fails at "rematch job should reach a terminal state" with nothing in any log. CI never sees it (one container, one process), so it presents as a local-only flake. `scripts/e2e-db-reset.sh` (via `make e2e-db`) terminates the attached sessions, watches ~3s for one to reconnect, and refuses to continue if one does — naming the process, and BEFORE the DROP, so a refused run leaves the other run's database intact (its connections are cut, which is recoverable; its data is not touched). Only a session with a pid that was NOT attached before the terminate counts as a reconnect: `pg_terminate_backend()` only signals, so a backend it just killed can still be listed for a moment, and counting that would refuse a run with nothing foreign attached. `make e2e-db` frees the standard E2E ports first (`e2e-ports-free`), so a leftover on those ports is killed rather than reported and the refusal is reserved for one that survives that. Do NOT reach for a bigger timeout — the job itself finishes in ~10ms |

| Capturing a tour's post-mutation state right after `waitForApi`                  | The response landing and the DOM re-rendering are DIFFERENT MOMENTS (measured: ~515ms for the dashboard's overdue widget to re-render after its refetch resolves). A capture taken in that window records the PRE-mutation UI alongside the POST-mutation API response — evidence that is internally contradictory but looks perfectly coherent to the judge, which will then produce a confident, well-cited, COMPLETELY FALSE regression report. The grounding rule cannot save you: the citation is real, the inference is not. Always wait for the OBSERVABLE CONSEQUENCE (`page.waitForFunction` on the thing that should have changed — a row gone, a count moved), bounded by a timeout, and record whether it happened in `fields` (e.g. `targetStillListed`, `reflectedWithinMs`). Do NOT throw on timeout: a real regression must be CAPTURED for the judge to grade, not killed before the capture. A racing tour is a false-positive generator and nothing downstream can detect it                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| Waiting on a network event after re-visiting a view the tour/spec already loaded | A per-query `staleTime` OVERRIDES `defaultOptions.queries`, so the `isPlaywright ? 0 : 5min` escape hatch in `frontend/src/lib/query-client.ts` does NOT reach any hook that pins its own — `useContacts` (2m), `usePrefetchContact` (2m), `useOverdueContacts` (5m), `useContactIDs` (5m), all in `use-contacts.ts`. Those four are the ones this has BITTEN, NOT the full set — a dozen-plus more pins live across the calendar, tasks, imports, sync, merge, suggestions, interaction-queue and accelerated-time hooks among others, so never rule this out just because your surface isn't contacts (`grep -rn staleTime frontend/src` for the live set). A round trip that returns to the SAME query key (same sort/order/search/filter) within that window is served from cache and issues NO REQUEST AT ALL, so `waitForApi`/`waitForResponse` burns its full timeout. The symptom is indistinguishable from a listener-arming race, so `expectApi` "fixes" nothing — there is no response to arm for. Gate on the RENDERED consequence instead (the restored row, the pager resolving to "N of M"), which is correct whether the view came from cache or a cold fetch. Beware the inverse too: `waitForApi` PEEKS the shared buffer with `.find()` and does not splice (`capture.ts`), so a same-path wait with no intervening `capture()` (the only drain) resolves instantly on the PREVIOUS leg's response and gates on nothing                                                    |
| Giving a JOURNEY intent `serves:` edges                                          | `bindIntentCaptures` binds `{intent.id} ∪ servedBy`, sorts by **tour name alphabetically**, then truncates at `INTENT_CAPTURE_CAP` (8). A journey walks behaviors that the PER-SURFACE tours also tag, so serves edges pull in those tours' captures — which sort earlier (`cadence-followup` < `dashboard` < `relationship-loop`) and fill the cap, SILENTLY EVICTING the journey's own captures. The judge then grades the journey on everything except the journey, over captures from multiple tours whose uuid placeholders are per-test (so one contact appears under two identities). A journey intent MUST have `servedBy: []` and bind by DIRECT CAPTURE TAG (tag every capture in the tour with the intent id). See CAD-038 / `relationship-loop.tour.ts`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
